# PENGUIN VR — Web Game Edition

A browser-first 3D penguin playground built with Three.js and WebXR. No Unity or Godot is used. The same web client can be hosted on HTTPS and then launched from an Android/Quest APK wrapper (TWA), subject to device/browser compatibility.

## Play locally

Use a local static web server; WebXR needs a secure context. With Python installed:

```powershell
cd PENGUIN-VR-WEB
py -m http.server 8080
```

Open `http://localhost:8080`. Desktop: WASD, mouse to look, Space to hop. Quest: deploy to HTTPS, open in Meta Quest Browser, then press **ENTER QUEST VR** and use controller thumbsticks. The exact Quest 3S WebXR input mapping still needs headset testing.

## Included playable systems

- 3D ice island, pond, igloos, ice arch, snow floes, and penguin characters.
- Desktop movement, pointer-look, jumping, mobile jump/throw buttons, and WebXR entry.
- Local practice penguins and round simulation for Penguin Tag, Hide & Seek, Infection, King of the Ice, Iceberg Race, and Snowball Paint.
- Local profile/name, fish-coin wallet, XP/levels, daily reward, shop, cosmetic locker/equipping, and local friends list saved in browser storage.
- Map themes: Frozen Island, Penguin Cove, Snowy Summit, Aurora Night.
- PWA manifest and service worker for installable web-app behavior.
- Existing account backend source preserved in `BackendService/` for future online integration.

## Important honest status

This is a more complete **single-player/local prototype**, not a finished production multiplayer game. The room-code screen and friends list are local UI only. Online matchmaking, server-authoritative movement/game rules, persistent cloud accounts, first-ever owner assignment, moderation, and voice/proximity chat still require a deployed secure multiplayer backend and service configuration. Owner tools intentionally remain locked; a client-only app must never assign the owner or trust a client claim. Mode AI and win conditions are starter gameplay and need balancing and Quest testing. No APK is generated by this ZIP.

## Publish and APK

1. Host the site over HTTPS (GitHub Pages can host static files; a custom domain helps for TWA verification).
2. Test the HTTPS site in Meta Quest Browser and confirm immersive WebXR works on Quest 3S.
3. For an Android launcher APK, package the hosted origin as a Trusted Web Activity (TWA) using Bubblewrap and configure Digital Asset Links at `/.well-known/assetlinks.json`. A TWA APK launches the hosted game; it is not a self-contained native game and depends on the website remaining online.
4. A Quest APK/TWA route may not expose immersive WebXR identically to Meta Quest Browser. Test this before treating the wrapper as the headset release. A normal Android WebView wrapper is not a reliable substitute for Quest Browser WebXR.

## Backend

`BackendService/` contains the account/social/moderation API source from the prior project. It is not automatically deployed or wired into this static client. Review `BackendService/README.md` and configure production secrets/identity provider before exposing it publicly. Do not publish secrets in the web client.
